Complete 7-Step Engineering Workflow

STEP 01

Planning & SRAM Formulation

Derived exact mathematical bounds for static SRAM consumption to guarantee zero Out-Of-Memory (OOM) heap panics on ESP32.

  • Strict zero dynamic malloc() policy at runtime.
  • SRAM budget strictly capped at 120 KB peak allocation.
  • KV-Cache formula: 2 x L x H x Ctx x d_head x 4B.
  • Calculated exact footprint: 81.92 KB KV-Cache.

STEP 05

Binary Weight Packing

Serialized PyTorch state dict into a packed binary (model_weights.bin, 820.78 KB) with explicit alignment.

  • 36-Byte Magic Header: 0x54504f45 ('TPOE').
  • Stores n_layer, n_head, n_embd, block_size, vocab_size.
  • Crucially skips PyTorch attn.bias causal mask buffer.
  • FP32 weight alignment matches C engine byte offsets.

STEP 06

ESP32 C Engine (XIP)

Zero-allocation C inference engine maps weights directly into MMU memory space via Flash XIP.

  • Uses esp_partition_mmap for 0 KB weight SRAM footprint.
  • On-device prompt BPE encoding using embedded merges.
  • Hardware-seeded xorshift32 PRNG for sampling.
  • Temperature (0.8) + Top-K (8) sampling algorithm.

Internal SRAM Allocation Formula & Derivation

ESP32-D0WD-V3 provides 520 KB total physical SRAM. FreeRTOS kernel and ESP-IDF drivers leave ~280 KB usable DRAM heap. To guarantee zero Out-Of-Memory heap panics, TinyPoet enforces a 120 KB peak DRAM allocation limit:

KV_Cache = 2 × Nlayer × Nhead × Nctx × dhead × 4 Bytes
KV_Cache = 2 × 2 × 4 × 64 × 20 × 4 = 81.92 KB

Total SRAM = KV_Cache (81.92 KB) + Activations (16.0 KB) + Stack (16.0 KB) = 113.92 KB ≤ 120.0 KB Limit 
// C Engine KV-Cache Allocation Structure (tinypoet_engine.h)
typedef struct {
    float key_cache[MAX_LAYERS][MAX_HEADS][MAX_BLOCK_SIZE][HEAD_DIM];   // (2 * 4 * 64 * 20 * 4) = 40.96 KB
    float val_cache[MAX_LAYERS][MAX_HEADS][MAX_BLOCK_SIZE][HEAD_DIM];   // (2 * 4 * 64 * 20 * 4) = 40.96 KB
} TinyPoetKVCache; // Total KV-Cache = 81.92 KB statically allocated on stack/DRAM
